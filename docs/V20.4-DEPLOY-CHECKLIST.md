# BARAMEEL V20.5 — Deployment Checklist

## Critical Supabase setting
For each Edge Function below, open **Settings** and set **Verify JWT with legacy secret = OFF**, then Save changes:

- player
- analytics
- scan
- admin-grant-ticket

Reason: the functions implement their own Authorization handling. The browser sends a current Supabase access token and the functions validate it with `admin.auth.getUser(token)`. The legacy gateway JWT check must not reject these current tokens before the function code runs.

## Functions
- player
- analytics
- scan
- admin-grant-ticket

## Secrets
- BARAMEEL_ADMIN_SECRET must exist under Edge Functions → Secrets.
- Never put a secret key or BARAMEEL_ADMIN_SECRET in GitHub.

## Browser config
`config.js` contains only the Supabase Project URL and Publishable key. The secret key is never included.

## First verification
1. Open GitHub Pages in a fresh/private browser session.
2. Wait at least 1–2 seconds on the first screen so the automatic player sync runs.
3. Open Supabase → Authentication → Users and confirm an anonymous user exists.
4. Open Table Editor → players and confirm a row exists.
5. Only after the player exists should you issue a scan ticket and test BARAMEEL-UNIVERSAL.

## QR architecture
There is one printed QR only: `BARAMEEL-UNIVERSAL`. A valid server-side scan ticket is required for a reward.
